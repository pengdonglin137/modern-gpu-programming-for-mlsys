(chap_tmem)=
# 特殊内存：TMEM

:::{admonition} 概览
:class: overview

- TMEM 是 Blackwell 独有的内存空间，由 `tcgen05` 使用。它是每个 SM 上的二维暂存器，有 128 行 Lane 和最多 512 列 Col。
- `tcgen05.mma` 将累加器写入 TMEM。分块缩放 MMA 也使用 TMEM 存储缩放因子。
- TMEM 通过 Lane 和 Col 寻址。在 TIRx 布局表示法中，这两个硬件轴写为 `TLane` 和 `TCol`。
- TMEM 不像寄存器那样分配。内核必须显式分配和释放它，以 32 列为单位。
- 普通的共享内存加载和存储不能访问 TMEM。数据通过专用的异步 `tcgen05` 指令在 TMEM、寄存器和共享内存之间移动。
:::

在 Hopper 及更早的 GPU 上，张量核心（{ref}`chap_tensor_cores`）累加器存在于寄存器中。这种模型很容易推理。MMA 指令产生一个寄存器片段，内核在计算阶段保持该片段存活，尾声代码稍后读取它、转换它并存储结果。

问题是寄存器压力。寄存器是每个线程的固定资源。随着 MMA 块变大，累加器片段也变大。在某个时刻，累加器开始挤占线程需要保持的其他值。更大的块有利于张量核心吞吐量，但将整个累加器保存在寄存器中使这些更大的块更难使用。

Blackwell 改变了数据路径的这一部分。`tcgen05` 的累加器不必在整个计算阶段都保存在寄存器中。相反，`tcgen05.mma` 将累加器写入张量内存（TMEM）。TMEM 是早期 NVIDIA GPU 没有的内存空间。它是 SM 上的二维暂存器，形状为 128 行 Lane 乘最多 512 列 Col，作用域限定为使用它的 CTA。

这个额外的内存空间使 Blackwell 能够支持更大的张量核心块，而无需将整个累加器强制放入每线程寄存器。但 TMEM 不像寄存器那样自动。编译器不会简单地将其作为普通寄存器存储分配。内核必须分配 TMEM，使用正确的布局寻址，使用正确的指令移入移出数据，并在 CTA 完成时释放它。

## 二维地址空间

TMEM 不是平坦的字节数组。它是一个二维地址空间。硬件将其两个坐标命名为 Lane 和 Col。有 128 行 Lane 和最多 512 列 Col。每列是 32 位。

这个形状很重要，因为 `tcgen05.mma` 使用这种二维结构将累加器写入 TMEM。TMEM 位置由 Lane 坐标和 Col 坐标描述，而不是像共享内存那样的单字节偏移。

当内核在 TIRx 中声明 TMEM 缓冲区时，它为缓冲区在这两个硬件坐标上指定一个布局。在布局表示法（{ref}`chap_data_layout`）中，我们将 TMEM Lane 轴写为 `TLane`，TMEM Col 轴写为 `TCol`。这些名称不是要替代官方硬件术语。它们是使 TMEM 维度在 DSL 中显式的布局轴名称。

例如，累加器块可以写为：

```text
S[(128, N) : (1@TLane, 1@TCol)]
```

这表示块沿硬件 Lane 维度有 128 行，沿硬件 Col 维度有 `N` 列。在布局表示法中，这两个维度显示为 `TLane` 和 `TCol`。布局是直接的：相邻行沿 `TLane` 移动，相邻列沿 `TCol` 移动。下图显示了该网格，硬件 Lane 沿 128 行向下，硬件 Col 横跨各列。

![TMEM 二维网格：TLane 行 × TCol 列](../img/tmem_grid.png)

主要观点是 TMEM 是块布局故事的一部分。它不仅仅是张量核心的隐藏后备存储。内核必须命名内存，从中分配列，并使用与 `tcgen05` 指令读写该内存方式匹配的布局。

## 分配

内核在使用 TMEM 之前，必须在其中预留空间。这与寄存器不同。寄存器由编译器分配。TMEM 由内核显式分配。

分配按 CTA 进行。CTA 中的一个 warp 请求一系列 TMEM 列。请求以 32 列为单位，请求的列数根据硬件分配规则向上取整。分配后，CTA 收到一个基 TMEM 地址。后续 `tcgen05` 指令使用该基地址访问预留区域。

将 TMEM 视为有预算的 CTA 资源很有用，就像共享内存一样。CTA 拥有其已分配的 TMEM 列。内核决定累加器、缩放因子或临时暂存需要多少列。当 CTA 完成时，必须释放分配。

这使 TMEM 成为内核资源规划的一部分。更大的累加器块可能提高张量核心吞吐量，但消耗更多 TMEM 列。分块缩放 MMA 可能需要额外的 TMEM 空间存储缩放因子。内核必须将这些用途纳入可用 TMEM 预算，就像必须将共享内存缓冲区纳入 SMEM 预算一样。

## 读写 TMEM

普通的 `ld.shared` 和 `st.shared` 指令不能访问 TMEM。TMEM 是独立的地址空间，因此数据通过专用的 `tcgen05` 指令移动。

有三条主要路径。

第一条路径是 `tcgen05.ld`，将数据从 TMEM 加载到寄存器。这是尾声代码在 MMA 阶段后使用的路径。累加器已在 TMEM 中产生，但尾声代码通常需要寄存器片段，以便进行类型转换、逐元素操作和存储最终结果。

在 DSL 层面，TMEM 加载分布在 warpgroup 中。它降低为四个 warp 级 `tcgen05.ld` 操作，每个 warp 一个。每个 warp 处理 128 个 TMEM Lane 行中的 32 行，因此四个 warp 共同覆盖完整的 Lane 维度。在布局表示法中，该完整维度是 `TLane` 轴。

指令本身来自一系列加载形状，如 `.16x64b`、`.16x128b`、`.16x256b`、`.32x32b` 和 `.16x32bx2`，重复因子从 `.x1` 到 `.x128`。选择的形状决定读取多少 TMEM 列以及每个线程接收多少寄存器。

重要的结果是寄存器片段布局。对于常见的尾声路径，lane `l` 从 TMEM 行 `l / 4` 和两列接收值。这产生了与前几代从 MMA 直接暴露的相同类型的每 lane 累加器片段（{ref}`chap_layout_generations`）。这种连续性很重要。它意味着 Blackwell 尾声代码可以重用已经用于 Ampere `mma` 或 Hopper `wgmma` 的相同寄存器级转换和存储结构，即使累加器在计算阶段存在于 TMEM 中。

![tcgen05.ld / st 在 m8n8 片段中将 TMEM 累加器移入和移出寄存器（lane l → 行 l/4，两列）](../img/tcgen05_ldst.svg)

第二条路径是 `tcgen05.st`，将数据从寄存器存回 TMEM。这是 `tcgen05.ld` 的反方向。当线程已持有寄存器片段并需要将其放入 TMEM 时使用。例如，某些操作数或中间值可能通过寄存器暂存，然后再写入 TMEM 供后续 `tcgen05` 操作使用。

第三条路径是 `tcgen05.cp`，将数据从共享内存复制到 TMEM。这是批量复制路径，通常用于分块缩放 MMA 的缩放因子。在这种情况下，TMA 或普通线程代码首先在共享内存中准备缩放数据，然后 `tcgen05.cp` 将其移动到张量核心期望的 TMEM 布局中。

所有三条路径都是异步的。`tcgen05.ld`、`tcgen05.st` 或 `tcgen05.cp` 指令可以在数据移动完成之前返回。因此内核必须在使用结果或重用存储之前使用正确的完成机制（{ref}`chap_async_barriers`）。

等待路径取决于指令。`tcgen05.ld` 通过 `tcgen05.wait::ld` 完成。`tcgen05.st` 通过 `tcgen05.wait::st` 完成。`tcgen05.cp` 与 `tcgen05.mma` 类似，通过提交组和 `mbarrier` 完成。如果数据从一组线程移交给另一组，内核可能还需要栅栏，以便接收线程按预期顺序看到已完成的写入。

TMEM 位于 Blackwell 张量核心数据路径的中间。TMA 将操作数暂存到共享内存。`tcgen05.mma` 读取其操作数并累加到 TMEM 中。对于分块缩放 MMA，缩放因子也可以暂存到 TMEM 中。计算阶段之后，`tcgen05.ld` 将累加器带回寄存器，尾声代码转换并存储最终输出。
